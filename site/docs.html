Overview & Quickstart

Summary: BIT is a 100% offline, privacy-first AI assistant for Android that runs language models, speech recognition, voice synthesis, and vector memory on local device hardware.

BIT eliminates cloud latency and subscription costs by packaging high-performance C++ inference engines into an Android application. Every user query, audio recording, document index, and long-term memory fact remains sealed on your physical phone storage.

The platform combines a Kotlin Jetpack Compose interface with native C++ llama.cpp JNI bindings, Sherpa-ONNX speech-to-text, Piper neural voice synthesis, and an FTS5 vector memory graph.

Note
BIT requires zero network permissions during normal operation. Internet access is only utilized if you choose to download GGUF models directly from HuggingFace or connect external cloud API fallbacks.

Install BIT on Android

Summary: Download and sideload the release APK directly on ARM64 or x86_64 Android devices running Android 8.0 (API level 26) or higher.

BIT is distributed directly through GitHub Releases and F-Droid rather than proprietary app stores. This enables unconstrained native C++ binary distribution and immediate open-source release cadences.

To install via Android Debug Bridge (ADB), connect your device via USB with Developer Options enabled and execute:

BASH 
adb install -r app-arm64-v8a-release.apk
Tip
For modern flagship devices (Snapdragon 8 Gen 2/3/4 or MediaTek Dimensity 9200/9300), use the arm64-v8a APK slice for maximum SIMD vector performance.
Next step: Load your first GGUF model →

Load your first GGUF model

Summary: Download a recommended GGUF model from the curated Model Store or import an existing `.gguf` file using the system file picker.

On first launch, BIT analyzes available system RAM and chipset capabilities to suggest an optimal model. Select a recommended entry like all-MiniLM-L6-v2-Q5_K_M.gguf for embeddings or Qwen2.5-1.5B-Instruct-Q4_K_M.gguf for general chat.

Alternatively, if you already have `.gguf` files on your device, tap Import Local Model in the Model Store and choose the file via the Storage Access Framework (SAF) picker.

Next step: On-device privacy architecture →

On-device privacy architecture

Summary: BIT processes all prompts, audio streams, and memory indices in-process on local silicon without external network calls.

Unlike cloud-based AI applications that transmit user audio and prompts to remote server farms, BIT executes the complete inference pipeline inside the app process space.

Memory notes and vector embeddings are stored in a local SQLite Room database (bit_db) and encrypted filesystem directories (AppPaths.aiMemoriesVault).

Warning
If you enable optional API provider fallbacks (e.g. OpenAI or Anthropic), queries routed to those providers will travel over HTTPS to third-party servers. On-device GGUF execution never connects to third-party servers.
Next step: GGUF quantization & silicon offload →

GGUF quantization & silicon offload

Summary: GGUF quantization shrinks model weights by 4x–8x while preserving reasoning quality, enabling fast execution on mobile CPU and GPU cores.

Full-precision 16-bit models require excessive RAM and memory bandwidth. GGUF quantization compresses weight matrices into 4-bit (`Q4_K_M`) or 5-bit (`Q5_K_M`) integer representations.

BIT's native C++ engine utilizes ARM NEON SIMD instructions, MediaTek APU extensions, and Qualcomm Hexagon DSP offloading to maximize tokens per second while minimizing battery drain.

Next step: Hybrid RAG & memory decay model →

Hybrid RAG & memory decay model

Summary: BIT pairs FTS5 keyword indexing with vector cosine similarity to retrieve relevant historical memories and documents for every prompt.

Traditional vector search can miss exact code symbols or proper nouns, while keyword search misses semantic context. BIT uses Reciprocal Rank Fusion (RRF) to merge results from both SQLite FTS5 keyword queries and 384-dimensional vector embeddings into a unified score.

Memory entries undergo automated decay: facts lose weight over time unless reinforced by user interaction, keeping context windows lean and relevant.

Set up local inference

Summary: Initialize and configure the `EmbeddingEngine` and `GlobalRagOrchestrator` programmatically in Kotlin.

`EmbeddingEngine` automatically detects valid `.gguf` model files at `AppPaths.embeddingModel(context)` and loads native handles cleanly.

Here is the exact initialization sequence executed on app startup:

KOTLIN 
// Initialize EmbeddingEngine from downloaded model file
val embeddingEngine = EmbeddingEngine()
val isReady = embeddingEngine.ensureInitialized(context)

if (isReady) {
    Log.d("Inference", "Embedding dimension: ${embeddingEngine.getDimension()}")
}

Next step: Enable hands-free voice mode →

Enable hands-free voice mode

Summary: Configure Sherpa-ONNX speech recognition, Piper TTS synthesis, and Silero VAD barge-in for continuous voice interaction.

Tap the microphone orb on the main screen to start Live Voice Mode. Speech input is captured via `AudioCaptureService` at 16kHz mono.

Silero Voice Activity Detection (VAD) monitors incoming audio continuously. If you speak while BIT is reading a response aloud, VAD detects barge-in, immediately cancels TTS output, and begins transcribing your new prompt.

Constrain tool calls with GBNF

Summary: Apply Grammar-Based Next-Token Filtering (GBNF) to force model outputs into syntactically valid JSON tool calls.

Standard language models can produce malformed JSON when attempting tool calls. BIT injects a strict GBNF grammar into the native sampler loop, forcing every generated token to follow the expected JSON schema.

GBNF 
root ::= tool-call
tool-call ::= "{" space "\"tool\":" space string "," space "\"args\":" space object "}"
string ::= "\"" [a-zA-Z0-9_-]+ "\""
object ::= "{" space "}" | "{" space string ":" space string "}"
space ::= [ \t\n]*

Architecture Overview

Summary: Core architectural design principles enabling real-time on-device and cloud hybrid inference seamlessly in Android.

BIT follows a strict multi-module design and leverages Jetpack Compose and MVVM for an ultra-responsive UI. Computationally heavy tasks (like local LLM generation or image diffusion) are carefully managed via Background/Foreground Services and JNI layer bridging to prevent UI jank.

1. UI Layer (Jetpack Compose & ViewModels)

The UI is fully declarative and reacts to StateFlow emissions from view models like `ChatViewModel`. User interactions are mapped to events that trigger background execution pipelines. The UI has no knowledge of whether the model being used is local (GGUF) or remote (Cloud API); it just consumes a unified `StreamEvent` interface.

2. Service Layer (Foreground Workers)

Android aggressively kills background processes. To allow models to persist in RAM when you minimize the app, BIT utilizes `LlmModelWorker` as a Foreground Service. This worker pins the native C++ engine in memory. `ModelDownloadService` manages asynchronous background downloading of large `.gguf` weights (which can be multi-gigabyte files).

3. Unified API Layer (`com.bit.api`)

The `com.bit.api` package encapsulates API handlers (Gemini, OpenAI, Claude, DeepSeek, Ollama, OpenRouter). Through the `ApiProvider` and `ApiRegistry` interfaces, all interactions—including tool-calling and stream parsing—are normalized before reaching the ViewModel.

4. Inference Engines (JNI/C++)

Native inference happens inside `llama-kt` (Text/VLM) and `DiffusionEngine` (Images). `llama.cpp` handles memory mapping (mmap) automatically, efficiently swapping pages from storage so devices with 6GB of RAM can run 8GB models.

Test BIT on device (QA & Tester Guide)

Summary: Complete verification protocol for QA engineers and manual testers validating APK installations, GGUF loading, RAG memory sync, and voice mode.

This test suite provides a comprehensive step-by-step procedure to confirm that a release build functions correctly on physical Android hardware before deployment.

Test Case 1: Clean APK Installation & Diagnostics

  1. Install release APK using adb install -r app-arm64-v8a-release.apk.
  2. Launch BIT. Confirm splash screen opens cleanly without crash loops.
  3. Navigate to Settings → Diagnostics and verify CPU architecture, detected RAM, and NPU features display accurately.

Test Case 2: Model Store Download & Local GGUF Load

  1. Open Model Store. Tap Download on all-MiniLM-L6-v2-Q5_K_M.gguf. Confirm progress bar advances to 100%.
  2. Tap Import Local Model and choose a local GGUF file via SAF file picker. Verify model displays in installed list.
  3. Send a prompt: "Hello, summarize your capabilities in 2 sentences." Confirm response generates smoothly.

Test Case 3: Memory Vault Single Write-Path & Node Eviction

  1. Send prompt: "Remember that my favorite programming language is Kotlin."
  2. Open Memory Vault tab. Confirm a new entry appears in the ai_memory folder.
  3. Verify the file ai_memory/*.md exists on disk and is present in Room DB table memory_notes.
  4. Delete the memory entry from UI. Verify the corresponding `.md` file is deleted from disk and purged from `NeuronGraph`.

Test Case 4: Live Voice Mode & VAD Barge-in

  1. Tap the microphone orb to initiate Live Voice Mode. Grant microphone permissions when prompted.
  2. Speak: "Tell me a story about space exploration." Confirm real-time STT transcription displays in UI.
  3. While Piper TTS is reading the response aloud, start speaking mid-sentence. Confirm TTS stops instantly (VAD barge-in) and enters listening state.
Tip
Save execution logs during QA testing via ADB: adb logcat -s "EmbeddingEngine:V" "GlobalRagOrchestrator:V" "MemoryPlugin:V".

Llama.kt & JNI pipeline spec

Summary: Architecture specification of Llama.kt in-process JNI bindings connecting Kotlin to C++ llama.cpp.

Llama.kt executes native C++ inference in-process via JNI (`com.dark.gguf_lib.EmbeddingEngine` and `LibLlamaEngine`). This avoids Android Inter-Process Communication (IPC) overhead.

PIPELINE DIAGRAM 
User Prompt ──► ChatViewModel ──► LlmModelWorker ──► JNI (libllama.so)
                                                         │
                                                         ▼
                                                C++ llama_eval()
                                                         │
                                                         ▼
                                             Stream Tokens via Flow

Memory Note & Room DB schemas

Summary: Table structure and frontmatter schema for `MemoryNote` objects stored in Room SQLite (`memory_notes`).

All notes are persisted as Markdown files with YAML frontmatter in `AppPaths.vaultRoot(context)` and mirrored in Room DB (`memory_notes` table).

KOTLIN 
@Entity(tableName = "memory_notes")
data class MemoryNote(
    @PrimaryKey val id: String = UUID.randomUUID().toString(),
    val title: String,
    val content: String,
    val folder: String = "notes",
    val noteType: String = "note",
    val filePath: String = "",
    val isAiMemoryEnabled: Boolean = true,
    val createdAt: Long = System.currentTimeMillis(),
    val updatedAt: Long = System.currentTimeMillis()
)

Version changelog

Summary: Official release notes and architectural changelog for BIT releases.

v1.9.3 (August 2026)

  • Single Write-Path Consolidation — Unified vault storage, Room DB, and RAG Graph reloads across MemoryPlugin, AiMemoryWriter, and ChatViewModel.
  • EmbeddingEngine Auto-Init — Added `ensureInitialized(context)` to automatically load downloaded embedding GGUF models on startup without requiring manual setup tab navigation.
  • Node Eviction on Edit & Delete — Implemented `removeSource(sourceId)` in `NeuronGraph` to purge stale nodes and dangling edges when notes are edited or deleted.
  • Graph Initialization Sync — Protected `GlobalRagOrchestrator` methods with `CompletableDeferred()` to prevent premature queries before graph population.
