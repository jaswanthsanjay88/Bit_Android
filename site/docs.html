Your First 5 Minutes Offline with BIT

A step-by-step hands-on guide taking a new user from installation on Google Play to their first verified local inference with zero internet connection.

Step 1 Install via Google Play Closed Testing Track

Authorized testers receive an invitation link to the Google Play Closed Testing track. Tap the opt-in link on your Android device and install BIT (v2.1.1, Build 82) directly from the Google Play Store. Automatic updates will stream directly to your phone as new releases are pushed.

Step 2 Hardware Auto-Discovery & Streamlined Model Selection

Upon first launch, BIT analyzes your device SoC and RAM. The setup screen guides you to lightweight models to ensure an instant download without memory pressure:

  • Ultra-Fast Setup (Devices under 4GB RAM): LFM2 350M (lfm2-350m-q8, ~400 MB). Liquid AI's ultra-lightweight model with instant response and lowest memory footprint.
  • Recommended Setup (Devices with 4GB+ RAM): Gemma 3 1B IT (gemma-3-1b-it-q4km, ~750 MB). Google's lightweight 1B model with high reasoning precision.
  • Power-User Models (3B - 7B): Higher-capacity models can be downloaded anytime post-onboarding from the Model Store tab.

Step 3 Verify Offline Air-Gap Mode & First Inference

Once the initial model finishes downloading:

  1. Swipe down your Android status bar and enable Airplane Mode (disable Wi-Fi and Cellular).
  2. Return to BIT and type in the prompt box: "Explain quantum computing in 2 sentences."
  3. Observe the token stream. The generation metrics bar below the response will report real-time speed in tokens per second (tok/s) and Time-to-First-Token (TTFT).

5. Model Parameter Configuration & Sampler Tuner

Customize low-level generation parameters per model. Set context buffer length, fine-tune temperature for creativity vs. deterministic coding, and enforce strict GBNF grammar constraints for JSON tool routing.

Click to zoom

UI Points & Controls Explained

1 Model Header & Metadata Banner

Displays the active model name, underlying tensor architecture, parameter quantization type, and base context limit.

2 Context Length Slider (n_ctx)

Controls context buffer allocation from 1,024 to 32,768 tokens. Lower context (2,048) minimizes RAM footprint; higher context (8,192+) enables deep document analysis.

3 Temperature Slider (0.0 to 1.5)

0.0 = Pure greedy deterministic output (ideal for code and math); 0.7 = Natural conversational balance; 1.2+ = Diverse creative writing.

4 Top-P (Nucleus Sampling) Control

Restricts candidate tokens to cumulative probability P (e.g. 0.9), filtering out low-probability tails while retaining vocabulary richness.

5 Top-K Sampling Control

Limits the candidate token pool to top K highest-probability tokens (default: 40), stabilizing generation output.

6 Repetition & Frequency Penalty

Penalizes already-generated tokens (1.0 to 1.5) to completely eliminate repetitive loops and degenerate phrasing.

7 System Persona Prompt Editor

Multi-line text editor to supply custom instructions (e.g. "You are a Kotlin expert who writes concise code") applied across all conversation turns.

8 GBNF Grammar Schema Selector

Enforces strict context-free grammars at the native token sampling stage for guaranteed valid JSON object outputs and function calling schemas.

9 GPU Offload Layers (n_gpu_layers)

Adjust how many transformer layers are offloaded to mobile GPU shaders via Vulkan/OpenCL. (0 = CPU only; max = maximum GPU acceleration).

DIÁTAXIS QUADRANT III — EXPLANATION

On-Device vs Cloud AI: Security & Latency

Architectural analysis of why on-device inference provides structural guarantees that cloud AI cannot match.

Cloud LLMs require transmitting user prompts, personal documents, and raw microphone audio over public transit networks to remote datacenters. Even with TLS encryption in transit, prompts are decrypted in cloud RAM and subject to provider retention policies, employee inspection, subpoena, or training data harvesting.

BIT operates on an air-gapped local execution model. The Android OS sandbox isolates BIT from other applications. Memory mappings (mmap) are held in private app memory, and the application requires zero network socket permissions during inference. If you discard or reset the application data, your history ceases to exist anywhere on Earth.

GGUF Quantization Mechanics on Silicon

How 16-bit floating-point weights are packed into 4-bit integer representations without catastrophic perplexity loss.

Standard foundation models are trained in 16-bit half-precision (FP16) or Brain Floating Point (BF16), requiring 2 bytes of RAM per parameter (e.g. 7 billion parameters = 14 GB of memory, far exceeding mobile limits).

BIT utilizes k-quantization GGUF formats (Q4_K_M, IQ4_XS). High-importance layers (attention matrices, feed-forward gates) retain higher bit precision, while low-impact bias vectors are quantized to 4 or 2 bits. On ARMv8.2-A+ mobile chipsets, these quantized blocks are computed using vectorized NEON dot-product instructions (SDOT/UDOT), delivering 3x–4x throughput improvements with virtually zero perceptual degradation in reasoning.

Hybrid RAG & Memory Vault Architecture

The dual-retrieval pipeline powering offline document grounding and persistent episodic memory.

Pure vector semantic search often misses exact alphanumeric identifiers (part numbers, dates, error codes), while pure BM25 full-text keyword search fails on conceptual queries. BIT employs a Reciprocal Rank Fusion (RRF) pipeline combining:

  • Dense Vector Retrieval: 384-dimensional on-device MiniLM embeddings calculating cosine distance over local document chunks.
  • Sparse Keyword Retrieval: SQLite FTS5 BM25 inverted index matching exact keywords and tokens.
  • RRF Merge Layer: Scores are normalized and merged before feeding top-k passages into the model context window.

GBNF Grammar Schemata Specifications

Formal context-free grammar specifications for constrained token sampling.

Below is the production GBNF grammar specification used by BIT for strict JSON tool-call routing:

tool_router.gbnf PRODUCTION GBNF 
root   ::= object
value  ::= object | array | string | number | ("true" | "false" | "null")
object ::= "{" ws ( pair ( "," ws pair )* )? ws "}"
pair   ::= string ":" ws value
array  ::= "[" ws ( value ( "," ws value )* )? ws "]"
string ::= "\"" ( [^"\\] | "\\" ( ["\\/bfnrt] | "u" [0-9a-fA-F] [0-9a-fA-F] [0-9a-fA-F] [0-9a-fA-F] ) )* "\""
number ::= ("-"? ([0-9] | [1-9] [0-9]*)) ("." [0-9]+)? ([eE] [-+]? [0-9]+)? ws
ws     ::= [ \t\n]*
