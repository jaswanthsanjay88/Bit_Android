Home

BIT is an offline AI engine for Android. It runs quantized GGUF language models, speech recognition, speech synthesis, document retrieval, and long-term memory entirely on-device — no network requests, no cloud inference, no subscriptions.

This manual covers everything from installing your first model to understanding how BIT routes a single message through its speech, reasoning, tool-calling, and memory subsystems.

Getting Started

Installing BIT

BIT ships as a direct APK download from GitHub Releases — it isn't distributed through the Play Store. Download the latest release (app-universal-release.apk or app-arm64-v8a-release.apk), allow installation from unknown sources if prompted, and install as you would any sideloaded Android app.

First Launch

On first open, BIT walks you through a short setup:

  1. Splash & Initialization — Engine initializes and verifies device hardware compatibility (chipset, available RAM, SIMD capabilities).
  2. Orientation — A brief overview of BIT's on-device privacy model and zero cloud dependency.
  3. Model Selection — Choose your first model to download. BIT recommends a model sized to your device's RAM and NPU/GPU capability automatically; you can override this and pick manually from the Model Store.

Sending Your First Message

Once a model finishes downloading, you land in the main chat screen. Type into "Ask me anything" or tap the microphone to speak. BIT loads the model into memory on first use — this takes a few seconds depending on model size — and stays loaded for the session to keep responses fast.

Choosing Between On-Device and API Models

BIT supports two inference paths behind one unified interface:

  • On-device, via BIT's own Kotlin-native engine (Llama.kt), running GGUF models fully locally.
  • API-based, if you choose to connect an external provider (OpenAI, Anthropic, Ollama, DeepSeek) for models too large to run on your hardware.

The two paths are interchangeable from the model picker — switching between them doesn't change how you use the app.

Models

Model Store

The Model Store is where you browse, download, and manage the GGUF models BIT can run. Models can be pulled directly from HuggingFace repositories or imported from local device storage via the Storage Access Framework (SAF) system file picker.

Each model entry shows its quantization level, file size, and estimated memory footprint for your device before you download it, so you can judge the size/speed/quality tradeoff up front.

Supported Formats

BIT runs GGUF-format models exclusively for on-device inference — the format used by llama.cpp and compatible engines, supporting quantization levels from highly compressed (Q4_K_M) to near-full precision (Q8_0, FP16). BIT has been tested with model families including Llama 3, Qwen 2.5, Gemma 2, Mistral, and LFM2; most GGUF-quantized instruction-tuned models in a compatible architecture will load cleanly.

Per-Model Configuration

Every model has its own settings panel, accessible from the model editor screen:

Temperature · 0.0 to 2.0 (Controls output randomness / creativity; default 0.7) Context Window · 512 to 32,768 tokens (Managed with a sliding-window KV cache) Repetition Penalty · 1.0 to 2.0 (Discourages the model from repeating phrases; default 1.1) Batch Size · 128 to 2,048 tokens (Prompt evaluation speed) Flash Attention · Toggle ON/OFF (Reduces KV cache memory bandwidth usage) System Prompt · Per-model custom system prompt override Thread Allocation · How many CPU threads the engine uses (balances speed vs thermals)

Settings are saved instantly to local Room database storage — no need to manually tap a save button.

Voice Subsystem

Speech-to-Text (STT)

BIT transcribes speech using an offline Whisper model running through the Sherpa-ONNX runtime, entirely on-device. No audio ever leaves your phone. Recognition begins as soon as you start speaking on 16kHz audio streams and is designed to keep pace with normal conversational speech.

Text-to-Speech (TTS)

Responses can be spoken back using Piper TTS, an offline neural voice synthesizer (vits-piper-en_US-amy-low, vits-piper-en_US-lessac-low, vits-ljs-tts). Speech is generated sentence-by-sentence as the model produces output — you start hearing a response before the model has finished generating the rest of it, rather than waiting for the full reply.

Live Voice Mode & VAD Barge-in

Live Voice Mode turns BIT into a hands-free conversational assistant, modeled on a simple state machine:

Idle ──► Listening ──► Thinking ──► Speaking
  • Idle — Waiting for audio input.
  • Listening — Actively capturing and transcribing your speech, shown by the orb animation responding to audio input in real time.
  • Thinking — The local model is generating a response.
  • Speaking — The response is being read aloud via Piper TTS.

Barge-in: You can interrupt BIT mid-response by simply starting to talk. This is detected using Silero VAD (voice activity detection) running continuously in the background, so BIT immediately stops speaking and returns to listening — no wake word or button press needed.

Agentic Tools

How Tool Calling Works

When a task requires more than generating text — searching the web, running a calculation, fetching structured device diagnostics — BIT routes the request through a tool-calling layer constrained by GBNF (grammar-based next-token filtering). This guarantees the model's tool call output is always valid, correctly structured JSON, rather than hoping the model happens to format it correctly.

For models with native tool-call tokens, BIT uses those tokens directly; for other models, it falls back to a two-stage selection process that first decides whether a tool is needed, then constrains generation to produce a valid call for the chosen tool.

Built-in Tools

BIT ships with built-in tools that a model can invoke mid-conversation, such as web search, page fetching, and system diagnostic inspection. Each tool call is executed locally or via requested endpoints, and its result is fed back into the model's context so it can incorporate real, current information into its answer.

Tool Call Transparency UI

Rather than hiding tool use behind a generic spinner, BIT displays a "Thinking process" panel listing each step as it happens — which tool was called, what parameters were passed, and how long execution took (e.g. web_search — 922ms). This panel is collapsible, so you can watch the reasoning happen live or fold it away once you have your answer.

Memory & Knowledge

Memory Vault

BIT can retain facts across separate conversations, not just within a single chat session. The Memory Vault automatically distills relevant details from your conversations into standalone memory entries, which are then available to inform future chats — without you having to repeat context every time.

Memories are configured with a decay model: older or less-reinforced facts naturally lose priority over time, keeping the memory set relevant rather than growing indefinitely.

Hybrid RAG

For document-grounded questions, BIT combines vector similarity search with traditional keyword search (BM25) — a hybrid approach that catches both semantic matches ("what did I say about deployment?") and exact-term matches ("find the line with MAX_RETRIES") in the same query.

Local Document Search

BIT can index local files — PDF, TXT, and Markdown — directly on-device, making them searchable and retrievable within a conversation without ever uploading them to an external server.

Architecture

Engine Overview (Llama.kt)

At the core of BIT is Llama.kt, a custom Kotlin-native inference engine built directly on native C++ llama.cpp JNI bindings, rather than a wrapper around a separate runtime process. This keeps model loading, inference, and the Android application in the same process space, eliminating IPC overhead.

Subsystem Pipeline Map

User Input (Mic / Text) │ ▼ Sherpa STT (16kHz Whisper) │ ▼ GBNF Router ──► Direct response / Tool call / Memory RAG lookup │ ▼ Llama.kt Core Inference (Native JNI) │ ├──► Piper TTS Voice (Synthesis) └──► Memory Vault & Hybrid RAG (Context enrichment)

Hardware Requirements

Performance scales directly with your device chipset and available RAM:

  • Minimum Specs — Android 10+ (API 29), 6 GB RAM, 64-bit ARM v8a processor (Runs 1B to 3B Q4_K_M models).
  • Recommended Specs — Snapdragon 8 Gen 2 / Gen 3 or equivalent, 12 GB+ RAM, Vulkan GPU / QNN NPU support (Runs 7B to 9B Q4_K_M models at 35+ t/s).

Customization & Data

Appearance & Glass Haze

BIT uses a dark, monochrome interface built with Jetpack Compose and Material Design 3 guidelines. A frosted-glass "Haze" blur effect is applied to surfaces like the navigation drawer and toolbars for visual depth without introducing distracting colors.

Navigation & Layout

A single restrained motion curve is used throughout the app rather than bouncy or spring animations, matching the website's dark aesthetic.

Updates & Local Data Storage

BIT checks for new releases via the GitHub API and can notify you when an update is available. All model files, conversation history, and memory vault data are stored locally in Room SQLite database files; nothing is synced to remote servers unless you explicitly connect an external API provider.

Frequently Asked Questions

Does BIT require an internet connection?

No — core functionality (chat, speech recognition, speech synthesis, GBNF tool calling, long-term memory, and local document search) runs 100% offline once your model is downloaded. Internet access is only needed to download models initially from HuggingFace, use the web search tool, or connect external API providers.

Can I use my own GGUF models?

Yes — import any compatible .gguf model file directly using the system file picker (SAF) in the Model Store.

Is my data sent anywhere?

No. Everything — models, chat logs, memory vault entries, and audio recordings — stays strictly on your Android device.

Why isn't BIT on the Play Store?

BIT is distributed directly on GitHub Releases to allow fast release cadences, unconstrained native C++ JNI binary distribution, and direct open-source community iteration without store review constraints.
